# 摘星者四环结构

摘星者控制器 ID 为 `gt_shanhai:star_lifter`。静态方块从当前渲染网格的零相位生成，基准半径为 68 格。Builder MCP 导入网格方块后，批量装配外环节点的 9 个方块，保存 Minecraft 1.20.1 NBT。GT JSON 和二进制均来自该导出。

## 坐标

Builder 原点位于导出包围盒最小角。X 向东，Y 向上，Z 向南。控制器正面朝东时，结构格点和 Minecraft 世界轴同向。渲染原点位于中心格的中心，包含三个 0.5 格偏移。其他水平朝向随主机绕 Y 轴旋转。

| 项目 | Builder 局部坐标或数值 |
| --- | --- |
| 结构尺寸，含正面交互净空 | 180 × 145 × 178 格 |
| 包围盒体积 | 4,645,800 格 |
| 几何中心 | (88, 72, 89) |
| 控制器 | (178, 72, 91) |
| 预留接口，均在同一朝东表面 | (178, 72, 90)、(178, 72, 92)、(178, 71, 91)、(178, 73, 91) |
| 强制空气 | 主机与四个接口正面各一格 |
| 方块数与校验位置数 | 113,944 个方块和 5 个空气位 |

预留接口为固定结构方块，当前摘星者运行既有演出，接口没有仓室能力。正面通过软锤切换演出。成型且启用时，方块模型和静态碰撞在已替代的格点停用。GT 仍从实际方块状态校验，固定操作节点始终保留。停止或失效时恢复静态模型和碰撞。

## 四环尺寸

## 重建导出

1. 用 JDK 21、当前工程的 JOML 依赖及 `StarLifterGeometry.java` 编译测试工具 `StarLifterMeshExport`，将标准输出保存为 `mesh.csv`。
2. 用 `python src/test/python/compile_star_lifter_structure.py mesh mesh.csv <工作目录>` 生成 NBT 和节点坐标表。Python 用到 `nbtlib`、`numpy` 和 `scipy`。
3. 在 Builder MCP 打开 `star-lifter-mesh-import.nbt`，按 `star-lifter-geometry.json` 的 `builder_plan` 批量放置控制节点，保存 `star-lifter-mesh-builder.nbt`。
4. 用 `python src/test/python/compile_star_lifter_structure.py compile <Builder NBT> <star-lifter-geometry.json> src/main/resources/assets` 更新两种格式。转换会检查 Builder 中全部网格方块及节点坐标。
5. 用 `python src/test/python/draw_star_lifter_structure.py <mesh.csv> <Builder NBT> <工作目录> <图纸目录>` 重绘投影、环面展开、截面和逐层坐标图。绘图另需 Pillow。

JSON 约 4.93 MB，按 GT 的 Z、Y、X 切片排列。运行时使用 GTL Additions 的 `GTLASB3` ASCII 行字典资源，约 1.22 MB。两份资源随同一个转换命令更新。测试通过生产使用的加载器逐行比较二进制和 JSON，并检查全部符号及四个水平朝向的中心变换。

## 破坏后切回静态

服务端在 GT 通知已成型摘星者有方块变更时，只核对变化位置的现有状态。发现不匹配即撤下演出和动态碰撞，后续由 GT 重新成型。已知的缺口修好前，跳过全结构搜索，也不为检查缺口强制载入区块。

客户端按结构中可替换方块实际分布刷新区段，控制器和预留接口保留原模型。下表以测试世界主机坐标 (602, 204, 514) 为例。区段数量随朝向和主机在区块内的偏移变化。

| 主机朝向 | 原包围盒区段 | 精确刷新区段 | 减少 |
| --- | ---: | ---: | ---: |
| 东 | 1,728 | 353 | 79.6% |
| 南 | 1,872 | 335 | 82.1% |
| 西 | 2,028 | 354 | 82.5% |
| 北 | 1,872 | 356 | 81.0% |

Forge 隔离存档启用 Radium 和 Oculus Complementary Unbound r5.4。使用同一控制器坐标和同一接口做五轮破坏、等待及修复。服务端 `setblock` 调用中位数从 65 ms 降到 34 ms，五轮分别为 88、43、65、38、78 ms 和 136、53、34、27、25 ms。优化轮第一次更慢，峰值收益仍未验证。每轮命令返回时动态碰撞已经撤下，五次补回接口均重新成型。在重进存档后也探测到动态碰撞恢复。

最终动画构建的同场景复测为 129、28、21、29、60 ms，中位数为 29 ms。切换仍有首轮尖峰。

首次实测导入用了 3.441 秒，包含整座模板放置和区块更新。导入返回后约 0.56 秒内探测到成型和动态碰撞，这项时间取决于测试探针的采样间隔。

四个水平朝向均通过 Forge 模板放置与成型验证。朝南、朝西与朝北时，还检查了旋转后的主机正面、变换后的恒星中心碰撞及拆除主机后的清理。

隔离存档调用 GT 的软锤操作入口后，关闭时中心动态碰撞撤下，重新启用时恢复。清掉测试用区块票并远离巨构后中心动态碰撞撤下，返回原区域后再次恢复。

JEI 的摘星者结构预览可由主机物品的用途打开。实际截图显示四环、恒星捕获层与材料列表，并验证了放大视图。JEI 上的 178 × 179 × 145（长 × 宽 × 高）对应实际占用方块，GT 资源另包含控制节点正面的空气位置。

## 恒星捕获层动画

静态恒星捕获层采用 64 张 16 × 16 关键帧，每两 tick 推进一张，中间插值。一个循环为 128 tick，按 20 TPS 计约 6.4 秒。纹理场在空间平铺和时间周期上连续，生成工具逐像素核对终点相位能与第一帧闭合。相邻关键帧的平均 RGB 通道变化为 7.53/255，最后一帧回到第一帧为 8.04/255，常规步进范围为 6.36–8.72/255。

用 `python src/test/python/generate_star_lifter_capture_texture.py <star_lifter_plasma.fsh> <stellar.png>` 可重新生成纹理，同目录的 `stellar.png.mcmeta` 控制游戏内播放。

Forge 的方块纹理图集实测载入 64 帧，静态恒星放大截图记录了不同时间点上的蓝白纹理变化。
