# 摘星者渲染性能与验收

## 渲染调用链

1. 成型主机或安装命令向 `StarLifterWorld` 登记中心、半径、朝向和起始刻。装置变化时同步快照。客户端用同一份装置坐标驱动动态渲染与本地碰撞查询，服务端继续根据游戏刻计算权威碰撞与生产。固定舱、仓室、主控面和汇流主体继续通过区块渲染。
2. `StarLifterRenderer` 在 `AFTER_ENTITIES` 消费客户端快照。渲染前用装置的运动包围盒剔除整座巨构，再分别检查四个环体的旋转包络，以及包含日冕的恒星范围。坐标先用双精度减去相机世界位置，再进入局部浮点矩阵。
3. 四环共用四个常驻 VBO，复用 Minecraft 的顺序四边形索引和方块图集。四个局部姿态继续使用 `StarLifterGeometry.Ring` 的有符号周期。世界渲染和终端预览都直接使用这些网格。终端的固定舱与汇流结构视图由另一块常驻网格提供，只在首次查看整机时构建。
4. `StarLifterEffects` 绘制恒星星面、切圆平面日冕、日珥、采集流和输运脉冲。固定扣箍根据运动外环的磁体通过相位发亮。顶点着色器用有界相位求值，按画质档共享参数网格。日冕的四边形也常驻 GPU。星面 Shader 用像素足迹抑制无法分辨的高频粒度。所有常驻网格共用渲染线程的一个本地暂存构建器，资源重载后关闭旧 VBO 并复用已有暂存空间。
5. 普通世界路径沿用深度测试和既有透明绘制顺序。Oculus 开启光影时环体仍在实体阶段绘制，星面和特效延迟到 `AFTER_LEVEL`，使用该帧保留的投影和主渲染目标。摘星者没有独占的 Bloom 或全屏后处理。光晕和约束效果由局部日冕和带状几何形成。采集效果没有独立粒子池或额外的体积步进。
6. `StarLifterTerminalPreview` 用独立颜色与深度缓冲合成预览。当前工作区的终端整机视图也复用星面、日冕和采集流。预览使用 `gameTime - startTick + partialTick` 逐帧计算旋转，暂停会保留角度，恢复会从该角度继续。世界旋转仍与碰撞使用相同的游戏时基。着色器交给 Forge 按资源重载管理，局部网格和查询由各自的所有者关闭。

## SHDT 数据采集

启动 Forge 客户端时设置 `-Dgt_shanhai.starLifter.profile=<GPU CSV 的绝对路径>`，进入世界后按相同路线运行，再通过退出世界保存采样。可选的 `-Dgt_shanhai.starLifter.profileStride=4` 控制阶段采样步长，默认每四帧采一次。帧开始间隔仍连续记录。普通路径与 Oculus 合成路径都能采样。GPU 查询在至少三帧后读取，未准备好的结果延迟处理，达到待处理上限时跳过新增查询。停用采集时不会创建 GPU 查询。

- `gpu.csv` 由 SHDT 的 `sh-render-profiler report --gpu` 直接读取。`WorldSubmission` 包含同一事件中实际提交的结构和特效。Oculus 的延迟特效另列于 `Composite`。
- `gpu.csv.stages.csv` 包含帧序号、阶段 CPU 经过时间、GPU 时间戳差、已统计的绘制、顶点、三角形、动态顶点字节和帧缓冲绑定计数。`gpu_ns=-1` 表示这项未采集。`Collectors` 包含采集批次，`RibbonDraw` 是其子阶段，二者会重叠。终端内复用的特效阶段带 `UIPreview.` 前缀。一个 GPU 批次同时绘制日珥、采集流和输运，按三者单独列 GPU 数据需要单独运行拆分的探针。
- 固定结构跟随 Minecraft 的区块构建与区块绘制。归墟后处理也拥有独立的量测入口。这两部分不会计入摘星者的各阶段。
- `RenderTick` 是 Forge 渲染事件之间的 CPU 经过时间，包含该区间的提交和等待。`FrameStartInterval` 是相邻渲染事件起点的间隔，包含渲染之外的客户端工作。显卡硬件换帧间隔需要独立采集。GPU 子阶段以成对时间戳观察，嵌套阶段不能叠加。
- SHDT `tick-capture` 捕获集成服务端的 Tick 窗口和超阈值栈。客户端 `render-issues` 的 Ctrl+F9 路径记录第 0、2、4 帧、坐标、朝向及渲染模组。图像中的闪烁、摩尔纹和运动连续性仍需要观看连续帧。

## 可重复场景

Builder MCP 的 1.20.1 摘星者模板是 179 × 145 × 178，占用 114,410 个方块。使用现有终端验收世界的独立镜像，测试主机位于 `(602, 204, 514)`，星心位于 `(512.5, 204.5, 512.5)`。固定机位测近景、远景、2／4／8 个可见动态装置和通过原生右键打开的终端。多实例场景使用同一真实成型主机和附加的客户端渲染装置。附加装置使用同一 GPU 网格和着色器，各自有独立变换与相位。

每个场景先预热 60 刻，再采 220 刻。关闭垂直同步，保留默认星面和采集效果。对照使用 Forge 47.4.16、Java 21、RTX 4060 Laptop GPU 和实际捕获的 2560 × 1601 画面，两轮都关闭光影。帧率指标基于相邻渲染起点间隔，平均值用总帧数除以总秒数。1% Low 和 0.1% Low 分别用最近秩 P99 和 P99.9 帧间隔折算。显存和 GPU 使用率来自同设备的 NVIDIA 遥测，JFR 可辅助核对 JVM 分配和 GC。

八装置场景，采集批次每帧顶点上传从约 737,348 字节降到约 71 字节，余量来自短时亮起的扣箍。日冕由每帧 768 字节降至 0。采集和输运的局部带网格保持每实例 5,760 个顶点与 2,880 个三角形，八座提交 46,080 个参数顶点。四环提交 641,856 个顶点与 320,928 个三角形，网格输入与前版相同。CPU 渲染事件窗口从 1.39 ms 降到 0.55 ms。

八装置的 11 秒窗中，JFR 归因到采集渲染调用栈的分配样本权重约为 2,975 MB → 10 MB。全 JVM GC 暂停总计 38.8 ms → 0 ms。JFR 权重是抽样估计，无法作为逐帧分配计数。同期显卡设备级平均占用为 67.0% → 64.2%，平均显存使用为 5,527 → 6,011 MiB。显存读数包含整合包和其他进程，无法归因到摘星者的专属 VBO。

SHDT 启动采样窗口内，近景的平均 MSPT 为 10.17 → 5.54，远景为 8.40 → 5.32，双装置为 4.10 → 5.45。SHDT 自动采集窗口没有覆盖八装置与终端，因此两项 MSPT 留空。慢刻调用栈包含区块加载、整合包初始化和服务端其他工作，本轮未改变摘星者的生产或碰撞更新规则。

对照终端的预览每次重画 CPU 为 0.124 → 0.115 ms，GPU 为 0.114 → 0.136 ms。采到预览实际重画的帧占比由 52% 升至 92%，与取消 30 Hz 姿态量化一致。整张终端界面的 P99 仍然恶化。两装置的 P99 和四／八装置的 0.1% Low 也存在回退。该轮终端对照使用两侧相同的原版贴图预览。后来并入的整机预览增加了星面、日冕和采集流，整帧性能仍需在相同特效配置下对照。

## 实机材料与后续验收

- Oculus 1.8.0 加载 Complementary Unbound r5.4，在同一画面启用归墟黑洞透镜的客户端预览。日志确认 `shaderpack=true`、`path=lens-after-composite`，并记录摘星者的 `Composite` 阶段。整合版完成原生资源重载后，远景、2／4／8 装置和终端继续绘制。该轮共 8,402 条记录，无 GPU 查询缺失。此场景使用黑洞预览入口和真实成型摘星者。
- 合入整机预览特效后，独立 Forge 夹具通过右键入口检查整机、单环、仅恒星和关闭预览。暂停时预览中央的 82,140 像素完全一致，恢复后有 24,506 个像素变化。阶段记录也确认了 `UIPreview` 下的星面、日冕和带状流独立计时。
- `starLifterStagingGpuProbe` 在隐藏 OpenGL 上下文中交替重建实体与特效网格 32 轮。两种格式复用同一个本地构建器，构建中断后可以继续上传，探针未记录 OpenGL 错误。
- 两轮普通对照与两轮光影验证均生成 SHDT 渲染取证，每次采第 0、2、4 帧及相机与模组元数据。工作区 `tmp/star-lifter-performance/` 内含原始数据、同机位对照、帧间隔曲线、动态 GIF、SHDT 报告和复测夹具。动图每四帧取一张，供目视核对几何与特效衔接。
- 持续运动稳定性、实际高刷新率的显示体验、长期显存趋势和多座真实生产主机共驻仍需独立量测。
