# FTBQ AE 提交器复核与重构

基线：`f7f83d412aff99400df6f92aa7f612491017b006`。API 核对使用仓库自带的 FTB Quests 2001.4.22、FTB Teams 2001.3.2、AE2 15.4.10 和 GTCEu 1.4.4。

## 修正

- 奖励的逐堆栈 SIMULATE 不预留共用容量，实际插入不足后原实现直接丢弃余量。改为独立 `FtbqRewardBuffer` 保存已领取但未交付的 key/long 数量，以 MODULATE 返回的实际数量扣减。余量存在时暂停新工作；存档与拆装保存余量。
- 补充显式机器掉落表和 `IDropSaveMachine`。否则本仓库 `ShanhaiBlockSelfDropMixin` 的空表兜底会绕过 GTCEu 保存机器数据的流程。创造模式中键复制不携带机器存档。
- 移除会调用直接发奖入口的反射回退；2001.4.22 只用 `markRewardAsClaimed` 标记，物品由提交器交付。
- 随机奖励先验证整张表，再一次性生成结果；空抽也记为领取。只支持原生 ItemReward、RandomReward 和 LootReward 的纯物品树；拒绝选择奖励、循环引用、未知子类与非物品结果，避免遗漏奖励或在提交前触发命令等副作用。ItemReward 的 post 在随附版本中为空实现。
- 精确扣物前判断是否为过滤器，候选物品统一经 ItemTask.test 验证，支持忽略/弱 NBT 匹配；遍历 AE key 快照，避免边遍历库存边修改。
- 拒绝锁定队伍和仅合成任务。入队入口自身也校验目标类型，不能只依赖网络包。领取玩家（包括离线玩家）当前队伍必须匹配绑定队伍。
- 队伍 UUID 改为只读，通过绑定按钮获取玩家真实队伍。跨队重绑清空旧队列；有待交付奖励时拒绝重绑。

## 验证

`FtbqRewardBufferTest` 的 6 项行为测试覆盖共用容量不足、部分写入重试、满网不修改状态、同类堆栈长整数合并、余量快照恢复、存储异常与数量校验。`FtbqAeSubmitterCompatibilitySourceTest` 的 3 项契约检查覆盖领取入口、存档/掉落接线与已有客户端 Mixin 入口。9 项定向检查通过。

完整 `compileJava` 已尝试：Forge 映射生成与 Kotlin 编译完成，但 Java 编译被外部 UI 依赖阻塞。主项目要求 SH-Better-UI 1.0.3；可获取的该库 main 为 1.0.0，缺少 `GlassColors`、`GlassSurface`，产生 11 个编译错误（生成器与星律 UI）。未修改这些无关源码，也未声称完整构建通过。

定向检查不替代完整 Forge 构建或游戏内验收。游戏验收重点：过滤器本体与 NBT 变体、锁定/仅合成任务、空抽/混合表、满网后扩容、卸载重载、带余量拆装、离队后重绑。

队伍领奖状态、机器方块与 AE 库存各自存档，本改动不提供进程崩溃时跨存档的原子事务保证。
