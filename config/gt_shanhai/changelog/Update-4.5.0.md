# gt_shanhai 4.5.0

发布日期：`2026 年 10 月 16 日`
此更新贡献者：**dishanhai**——`核心代码贡献者`

4.4.0 标签里已经放进创造物品栏、但当时公告没写的内容，也补在这里。

## 山海样板生成工具

- 新增`山海样板生成工具`。组装：终极终端、样板编码终端、数据棒 ×4、EV 电路 ×4、EV 传感器 ×2、EV 发射器 ×2、焊接合金。
- 手持右键打开。从背包或 JEI 拖入 GT 机器，右键移除。这一步不消耗物品。
- 先选配方类型，再选电路。`不限电路`是该类型全部配方。`无电路`只要不需要电路的配方。
- 筛选可以要求输入或输出包含某些物品、流体，也可以排除。每组 7 格，从 JEI 拖入，不消耗。左键选中格子后改标签，右键清除。包含是命中任意一格即可，排除是命中任意一格即去掉。一侧留空则这一侧不限制。精确匹配留空时，不会再被当成一个空标签。
- 也可以用名称或 ID 写文字条件，空格分隔，和格子同时生效。
- `扩展`里可以调输入倍率、输出额外倍率，范围都是 1 到 64。最终输出倍率是两者相乘。数量会溢出的配方会生成失败。
- 扩展还可以限制最低、最高电压，按配方 ID、耗电、耗时排序，以及用配方 ID 关键词筛选。
- `跳过已有`打开时，背包里已经有本工具标记过的同一配方样板，就不再生成。
- 预览里勾选后免费生成。样板写入机器模式、制作者和配方标记。背包放不下的掉在脚边。生成可以中途取消，配方表更新后要取消剩余任务再重新筛选。
- 生成之后可以填入仓室。点按钮关掉界面，再右键星律样板总成、样板供应器或其他能收样板的容器。装不下的留在原地，可以继续右键别的仓室。配方失效时停止填入。
- 预设保存在 `config/gt_shanhai/pattern-generator-presets`。格式是 `gt_shanhai:pattern_generator`。保存机器、筛选、倍率和已勾选配方。把别人分享的文件放进这个目录后刷新。缺失的配方会跳过，剩下的仍可用。

## 星律通配样板

- 样板生成工具可以把已勾选配方收成一张`星律通配样板`。没改勾选时，收的就是当前匹配结果。一张最多 4096 条配方。
- 放进星律样板总成的通配符槽后，按记录的配方 ID 展开，不走材料通配符。
- 悬停会写出配方数量、配方类型、输入输出倍率和前几条配方。右键打开内部样板，悬停单张可看材料。
- 右键界面上面有 9 个放入格，下面是自己的物品栏。放进编码样板后，匹配到配方 ID 就写进这张通配样板。没匹配上的留在放入格，并写出没配上的张数。
- 样板生成工具原来写下的配方单独留着。从放入格拿走样板，只撤掉这次手动加进去的条目。放不下 4096 条上限的不会写进去。空样板会按放进去的配方补上配方类型；已经有类型的保持不动。
- 物品栏图标在四个角叠前几条配方的产出物品，同一种物品只占一角，最多四个。手上和掉落物仍是样板本体。

## 山海无线样板管理终端

- 星律样板总成所在分组的标题右侧改为`星`按钮，点开控制菜单。菜单项：样板界面、库存输入、产出倍率、通配符样板、共享输入、样板行为、返还库存。
- 同一分组里有多台星律时，先选`星律 1`、`星律 2`，再点功能。每台单独生效。
- 菜单左侧显示当前这一台的名称、宿主、坐标、样板占用、通配符、产出倍率、电路、告警和网络在线状态。
- 坐标可以点击传送。目标区块没加载，或者那个位置已经不是星律样板总成时，拒绝传送。
- 下面另有挂载主机的数量、配方类型、当前工作状态和主机坐标。代理一行给出数量，悬停列出每台代理的坐标和成型状态。
- 星律广播过卡死样板时，面板里是一行摘要。悬停按槽位、原因、原料、输出、主机配方类型和样板配方类型分行展开。
- 中键点击样板槽，仍然打开该槽的催化剂配置。
- 含星律的分组会隐藏 ExtendedAE Plus 原来的 UI 按钮。普通样板供应器分组仍走原来的按钮。

## 星律样板总成

- 单配方类型切换的宿主，现在可以同时跑它拥有的其他类型。大型切割机停在切割机时，车床样板也会进入虚拟执行链。
- 这一轮执行不会改掉界面上选中的配方类型，选中下标保持不动。
- 宿主本身没有的配方类型，仍由配置里的破限开关决定能不能跑。
- 原料相同的样板按槽隔开，不会互相串单。和宿主配方类型对不上，或槽位卡死时，对应槽亮红框。
- 通配符槽改成按页配置，接受星律通配样板。默认每页 10 格、2 页，共 20 格。界面上有 `<<` / `>>` 翻页。
- 格数和页数在模组配置的`配方类型样板总成`里。`通配符槽每页格数`是 1 到 16，`通配符槽页数`是 1 到 64。改完要重启，已放置的总成在下次区块加载时采用。调小会把高位槽里的通配样板掉在机器位置。
- 库存输入仍是真正扣料时才从 ME 提取。
- 物品说明改成按样板、供料、接入三段来写，和现在的界面一致。

## 创始演算器

- `创始演算器`在 4.4.0 标签中已进入创造模式物品栏。它没有机器逻辑。
- 原初因果编织可以合成它。材料里有最大世线板、寰宇模拟单元、寰宇电路重组单元和万象原核。
- 它作为不消耗输入，写进创造箱子、创造储罐、四条星门超时空装配线、永恒世线板 8 倍重组，以及终焉聚合枢纽、`universal_parallel_overdriver`、永恒世线板、创造模块这几条新配方。

## 配方修改器

- 增加`默认开启` / `默认关闭`。导出的 JSON 会写 `defaultEnabled`。设成关闭再提交时，当前这条配方也会关掉。
- `/配方列表已禁用` 会计入 JSON 里默认关闭的配方，分页列出，同一个 ID 不重复。
- 编辑器打开时，JEI 材料列表和搜索框停在书签、历史按钮上方，按 JEI 15.49 的书签高度留空。
- 打开一条配方时，输入和输出都先摆满一页：物品 16 格、流体 16 格。条目更多的配方按实际数量保留，多出来的翻到后面。

## 商店

- 没选商品时，右侧详情列出购买步骤和常用入口。网格底部改成两行轮换提示。悬停顶栏按钮和商品时，会说明这一下会做什么。编辑权另外提示批量勾选、清空和拖动排序。分类或搜索为空时，网格里会写下一步该点哪里。
- 货币中心没选货币时，右侧写出存入、兑换、转星火和提取的步骤。币种列表下方两行轮换提示。悬停币种、星火、AE 状态和各个按钮时，会说明这一下做什么。特殊货币会标明要去兑换中心。AE 模式仍在商店顶栏开关。
- 阶段还没解锁时，可以点`AE下单补齐阶段前置`，按阶段固定物品下单。
- 打开商店编辑模式后，全屏锁定层会拿掉，这个下单按钮仍留在阶段提交旁边。
- 组合商品的获得预览可以换行，不再把一行放不下的收成 `+N`。悬停物品格会带上原版物品提示和精确数量。流体仍用名称和数量。

## 超级磁盘阵列与 ME 终端

- 里面已经有物品的磁盘、另一张超级磁盘阵列、虚拟盘，都不能再嵌进超级磁盘阵列或磁盘仓。它们按普通物品记账，不展开内部库存。
- 终端模拟插入和真实插入使用同一结论。以前会先按放入成功扣掉光标，真实插入却失败，物品就没了。
- ME 终端整格取空后，这一格会从界面消失。以前数量变成 0 的物品会一直留在终端上。

## 兼容

- `太素衍化`同时兼容 gtladditions 3.2 和 3.3.1。3.2 读公开字段，3.3.1 改走 getter。
- 星律跨类型查找对准 GTLCore 改写后的配方迭代。

## 配置界面

- `虚拟物品提供器`增加`编码时写入配方 ID`和`编码时写入虚拟供应器`。两个都默认开启。样板编码终端标题旁边也有同样的开关，点一下就写进这份配置。
- 配方 ID 关掉之后，编码和快速上传都不写。已经写在旧样板上的 ID 不会被清掉。
- 虚拟供应器关掉之后，编码和快速上传都保留原来的物品或流体，不把不消耗输入写成虚拟供应器。
- 编码页上还有`副产物下单`。它只作用于这一页的编码按钮。快速上传仍用 JEI 上自己的按钮。

## 样板编码

- 样板上已经有配方 ID 时，再编码会按这个 ID 锚定配方。可以改、可以删输入，旧 ID 不会套到另一条配方上。
- 快速编写的成功消息会带上配方类型的本地化名称和配方 ID。不同 ID 超过 3 个时，只列出前 3 个，并写出总数。

## 星空可请求标签库存

- 自动拉进来的物品或流体，被从槽里清掉或换成别的之后，会记下来，之后不再自动补回。
- 再把同一件放回去，这条记录就取消。
- 标签匹配不会占用样板已经要的目标、手动留下的格子，以及上面记下的那些目标。

## 星律库存请求

- `标签拉取`页不再按`物1`、`流2`分页列出维持量和批量。白名单、黑名单和`可请求`总开关仍在这一页。
- 打开`库存输入`，空手左键已经拉进来的物品或流体，这一格会亮起。槽下面写出名称，并给出这一格的开关、`维持`、`批量`和`确定`。
- 没选中时，槽下面写着`左键已拉取的物品或流体`。
- 手上拿着东西时，左键仍是放入。右键仍是清除。选中的格子被清掉之后，选择取消，槽下面回到未选中。
- `维持`是网络持有量低于这个数才请求，流体单位和库存槽相同。`批量`是每次合成的数量，不超过离维持量的缺口。改完要点`确定`才会写上。
- 总开关打开时，低于维持量按批量合成，产物回到网络。关掉后只使用网络里已有的库存。每一格的开关可以单独停掉，默认开着。
- 星律样板总成的物品说明同步改成：左键已拉取的物品或流体，可以改维持量和批量。

## 量子合成与副产物下单

- 副产物下单把同一次样板的全部产出放在等待列表里。主产物先入库时不再提前收工，其余产物都进网络之后才结清。
- 不消耗输入只做一次在场检查。推送和发配不会按整批下单次数把实料需求放大。虚拟在场缺了，不再报成没有样板。

## 原初寰宇模拟核心

- 新增原初模块`原初寰宇模拟核心`。装在原始终焉引擎的模块位上，处理`宇宙模拟`。
- 并行、线程倍率和无线供电沿用原初模块。并行上限由物质模块槽里的模块等级决定。没有创世之眼或奥术星图的专属机制。

## 掉落与检索

- 没有战利品表的 `gt_shanhai` 方块，破坏后掉自己。已经写了战利品表的仍走原表。
- 拆掉原初模块控制器时，物质模块槽、线程倍率槽和六个额外挂载槽里的物品会掉出来。子类另外持久化、又不在这三组槽里的物品也会掉。
- 原初模块不再因为样板仓数量每刻跳动就重搜整张配方表。电路，以及只有 1 格的选择槽，物品种类或电路号一变仍立刻重搜。
- 空转时，连续的库存通知不会把模块叫醒去做全量搜索。安静超过 1 刻之后的第一次通知仍会解除空转，补上料可以开工。数量、并行和扣料每一轮照算。代理执行者和其他内容一变就必须重搜的机器保持原样。

## 配方加载

- 进服时的配方统计读服务器启动后预先算好的快照。配方重载会丢掉这份快照，下次再算。
- 一份 JSON 如果和配方表里已有配方的消耗材料、产物相同，会提示被当成重复配方移除，最多列出 3 个对上的配方 id。不消耗的输入，例如模具、电路、`wzcz`，不参与这次比较。

## 文本

- 流动文字新增`全`、`随机`、`完全随机`。`全`把已有流动色板接在一起。`随机`在这些色板之间平滑切换。`完全随机`逐字变色，字和字之间平滑过渡。
- 原有色板补了中文别名，例如`金色`、`火焰`、`樱花`、`正文金色`。别名和原来的英文键是同一套颜色。
