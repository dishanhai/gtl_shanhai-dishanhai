# gt_shanhai 4.5.1

发布日期：`2026 年 10 月 18 日`
此更新贡献者：**dishanhai**——`核心代码贡献者`

接在 4.5.0 后面。商店、货币、星律通配样板、样板强匹配、原初模块和配方都有改动。

## 新的问题反馈渠道：
- https://docs.qq.com/sheet/DYWFtSEtvTWVodkJn?tab=000002

## 商店

- 商品编辑里，星火成本上方有`设为免费`。点开后清空星火、币种、物品、流体、无线电网 EU 五条通道，购买不扣任何东西。再点`免费中`可以重新填成本，刚才清掉的花费要自己填回去。
- 五条通道都空、又没点`设为免费`时，保存会被拦住，提示去点那个按钮。已经存成空成本的商品按免费商品生效。
- 免费商品可以购买。出售会被拦住，提示`免费商品不能出售`。详情和花费预览写`免费`，悬停写`免费商品不可出售`。
- 详情页按奖励表写出每一项的数量和百分比。随机模式标`百分比为单次抽取`。自选模式标`百分比为表内权重`，给哪一项仍由玩家点选。全部模式写`必得`。FTBQ 表里商店不发放的非物品奖励会标出来。表还没同步时写`奖励表未同步或不存在`。
- 选择奖励界面右侧也写出数量和表内权重百分比。
- 商店设置新增`获取预览模式`。方格是图标格，奖励表在格子下方写概率，获得和花费在格子下方写数量。条形是名称列表，概率或数量写在右侧。选择写进 `config/gt_shanhai/shop_client_ui.json` 的 `rewardPreview`。默认是条形；只有明确存过 `grid` 的旧客户端仍是方格。
- 商店设置内容变多之后可以滚动，滚出视口的输入框会隐藏。
- 商品描述编辑区可以切换中文输入法。`ESC` 关闭、`Ctrl+回车` 确认仍可用。
- 新增`AE 注入限额`。商店设置和模组配置里都有，配置键是 `shop.aeInjectMin`，默认 64，最小 1。AE 模式下，单种物品这次数量低于这个数就进背包，达到才注入 AE。设 1 时，网络吃得下就注入。流体不受这项影响。`AE 禁止注入`打开时这项不生效。整批已经达到 SDA 打包阈值时，没进 AE 的仍随整批打包。
- AE 模式下，花费预览会标出绑定网络里有没有对应样板：有样板写`可下单`，没有写`无样板`，未绑定写`未绑定`。条形预览写在数量左边，方格预览写在悬停提示里。
- 详情页有确定缺口时，`补齐全部缺口`下面多一行`收藏缺失`。只把缺的币种、物品和流体写进 JEI 收藏，已经收藏的不重复。JEI 没装或还没就绪会提示不可用。
- 商店设置新增`记住选取与搜索`，默认开。关闭商店再打开会还原上次选中的商品和搜索词，只记在这台客户端的 `shop_client_ui.json`。关掉开关时会清掉已经存下的内容。
- 悬停 `currency_rates.json` 里有的货币，提示写`按住 [按键] 进入货币中心`。按住和商店相同的快捷键，默认 `S`，按住约半秒。先校验山海钱包再打开商店，下一刻进入货币中心并选中这一种币。没带钱包时服务端拒绝；10 秒内商店没打开，这次定位作废。普通商品悬停仍走原来的商店跳转。

## 货币中心

- `currency_rates.json` 里的数字仍是面值，铜币为 1，往上按 4 的幂次排。文件不会被这次更新改写。
- 兑星火和币种互换改按兑星火价结算。白金及以下（铂金币，面值 ≤ 256）1 面值换 1 星火，铜币到铂金币买东西跟以前一样。
- 更高的币面值每 ×4，星火只 ×2。锇币面值 1024，兑星火 512。时空币面值 1048576，兑星火 16384。
- 币种互换用两边的兑星火价：`floor(源数量 × 源兑星火价 / 目标兑星火价)`。先把高阶币拆成铜币再转星火，换不到旧的满额面值。
- 转成星火和星火转出是同一价格，按这个价格来回换不亏不赚。高阶币换成星火比旧面值少，用星火换回高阶币也比旧面值便宜。
- 货币列表悬停和右侧详情同时写出面值和兑星火价。兑换、转星火、快速售出的提示同步改成兑星火价。特殊货币仍不参与比例兑换和转星火，去兑换中心。
- 新增 `config/gt_shanhai/currency_stages.json`。`stagePrefix` 是阶段前缀，默认`杂货/正常`；`coins` 把每种货币挂到一个阶段名上，默认从铜币的 `ulv` 起步，后面按阶段顺序排。完整路径是`前缀/阶段名`。
- 没提交过对应阶段时，兑换、转星火、星火转出会被拒绝，并提示缺的是哪个阶段，和商店购买用的是同一份阶段提交。存进钱包和提取实体币不受阶段影响。
- 快速售出会跳过未解锁的币种，消息里写出跳过了几种；全都没解锁时单独提示先去提交阶段。
- 货币中心列表在币名右侧显示阶段短标记，例如 `HV`。已解锁是灰色，未解锁是红色并带`锁`字。
- 货币列表悬停写出完整阶段路径、已解锁/未解锁状态。未解锁时还会列出这个阶段要一次性提交的物品和数量；详情页货币名后面也显示同样的阶段和状态，悬停可看解锁条件。
- 阶段没配置、或者该阶段路径没有配置提交物品的货币不锁。
- 新建 `currency_stages.json` 时，`dishanhai:transcendentmetal_coin` 默认挂在 `max`，不再写 `max+`。已经生成过的文件不会自动改写，需要的话手动改 `coins` 里的那一项。

## 星律通配样板

- 右键界面分成`自动生成`和`手动更改`。两组共用同一块区域，点哪组显示哪组。
- `自动生成`只展示样板生成工具写下的底稿。放进放入格、后来写进去的配方不出现在这一页。
- `手动更改`是 14 列 × 5 行，共 70 格。放入编码样板后，匹配到配方 ID 就写进这张通配样板。取出样板后撤下对应配方。旧存档放入格不足 70 格时，只读已经有的格子。
- 没有自动配方、放入格里已经有样板时，打开就停在`手动更改`。
- 顶栏计数改成`自动 x / y 张 · 手动 z 张`。
- 星律样板总成的物品说明改成 20 个通配符槽。格数和页数仍由模组配置决定，默认每页 10 格、2 页。
- 刷新通配底稿或重建样板时，样板里已经写下的配方 ID 会保留，不再被配方类型重写覆盖。样板生成工具写下的自动底稿同样按这个规则处理。

## 样板强匹配

- 配方类型样板总线新增`样板强匹配`侧栏页，星律样板管理界面和星律终端远程侧栏都能打开。开关按这台总成保存。
- 打开后，样板必须同时带配方类型和完整配方 ID，并且 ID 路径是`配方类型路径/xxx`。执行时只认这一条配方，不再从样板内容推断替代配方。
- 缺配方类型、缺配方 ID、ID 解析不到或类型对不上的样板会在格子上标红，并不参与扣料。
- 关闭时按样板内容指纹匹配，材料相同或相近的替代配方仍可能被执行。这个开关默认关闭。
- 关掉开关只清掉强匹配标出的红色，不误清其他警告。
- 样板保存的配方 ID 只在它声明的配方类型里解析：先按 ID 直接取，再核对命名空间和路径后缀，避免串到其他类型的同名或相近配方。
- 远程侧栏和总成上的开关是同一份，改完立刻生效。
- 校验接在配方类型样板总线扣料之前。
- 样板配方类型只按格子里当前样板读取，格子内容变化时才重算，不再每次翻页都重扫全部格子。
- 强匹配页写出当前结果。没开是`强匹配未开启`。开了且没有被拒的样板是`强匹配：当前没有拒绝的样板`。有被拒的样板时写出槽数和第一条原因。
- 被拒的格子悬停写出原因，一共四种：`没有配方 ID 或配方类型`、`配方 ID 缺少类型前缀`、`该类型下找不到这个配方`、`样板内容与配方 ID 不符`。第一种只写原因。后三种再带上配方 ID，或对不上的材料。
- Jade 看星律时，强匹配开着会多一行。没有拒绝写`强匹配: 开启`，有拒绝就把第一条原因标红。
- 星律卡死告警多一行样板配方 ID 和样板配方类型。同一条拒绝不会在服务端日志里按刻连刷。
- 并行和概率折算会给内部配方 ID 加上槽位后缀。强匹配比对时认样板上保存的公开配方 ID，这类副本不会被判成`样板内容与配方 ID 不符`。
- 配方输入是物品标签、标签里有多种物品时，样板写其中任意一种都能对上。以前往往只认标签缓存里的那一个展示物品。

## 原初逆熵构成

- 原初永恒熔炼炉新增配方类型`原初逆熵构成`。追加在星焰跃迁后面，已经保存的配方类型下标不变。
