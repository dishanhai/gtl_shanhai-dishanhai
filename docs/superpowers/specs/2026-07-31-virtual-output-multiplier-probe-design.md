# 虚拟倍率探测设计

## 目标

让主机在可选能力开启时，通过一条隐藏虚拟配方自测当前产出倍率，并把这个结果作为星律样板总成下单时的最终倍率来源之一。样板本体不改，现有线程倍率、固定广播倍率和 `IOutputMultiplierSource` 聚合逻辑继续保留。

## 设计

1. 新增一个只读探测接口，供支持的主机和模块实现。
2. 主机探测结果通过内部虚拟配方运行现有 `setupRecipe` / 倍率修正链路得到，返回 `long` 倍率。
3. `OutputMultiplierResolver` 在能力开启时优先读取探测结果；同一个 `source key` 下，探测结果覆盖普通来源结果，避免主机与模块双算。
4. 星律样板总成只消费 resolver 的最终值，不再关心倍率来自探测、线程还是广播。

## 开关

探测能力默认关闭。关闭时完全保持当前行为，继续走现有 `IOutputMultiplierSource` 读取路径。开启时才对支持探测的主机执行虚拟配方检测。

## 虚拟配方约束

- 只用于内部探测，不进入 AE 可见样板列表。
- 不写持久 NBT，不改库存，不改样板槽。
- 探测失败、主机未成型或逻辑不可用时一律回退到 `1x`。
- 探测结果需要缓存，缓存失效条件包含结构变化、模块变化、配置切换和配方逻辑重置。

## 数据流

1. 星律或分子端口请求宿主倍率。
2. `OutputMultiplierResolver` 收集控制器和部件。
3. 若对象支持探测且开关开启，则运行虚拟配方并读取探测倍率。
4. 继续叠乘线程倍率、固定广播倍率和其它 `IOutputMultiplierSource` 来源。
5. 结果回到星律样板重写链，作为最终输出数量倍率。

## 验证

- 源码契约测试覆盖探测接口、resolver 优先级和 fallback 路径。
- 星律专项测试覆盖开启/关闭探测时的最终倍率一致性。
- 原初专项测试覆盖主机与模块共享同一探测 key，避免重复叠乘。
- 定向 `gradle test` 后再跑一次编译验证。
