## 根因與相容性

`Session.uiAction` 會將業務結果存入 `status`，一般選取與空格清除的伺服端拒絕也更新同一狀態；`Session.message` 已是這些回饋的共同來源。舊主介面卻因 `lastResult != null` 永久隱藏這份訊息，因此成功回執會遮住後續 `ui.list_changed`。

現在只在 pending 尚未結束時覆蓋訊息，配對完成即顯示伺服端同步文字。`LibraryController`、`Pending`、同步橋及業務程式碼均未修改：保留 requestId／action／target 三者配對、單線請求及逾時只刷新。沒有新增固定延遲、訊息字串比較或訊息先後序協定。完成後的訊息使用既有同步文字的中性色，pending 保持強調色，避免舊結果顏色誤套到新訊息。

主介面只切換兩個文字控件的 visible，未關閉 active；LDLib `WidgetGroup.detectAndSendChanges`／`updateScreen` 依 active 處理子控件，隱藏期間仍會接收文字更新。覆蓋解除後會使用現有同步內容。

## 可測接點

同 package 可呼叫 `StellarCloudLibraryUi.Feedback.visible(controller, serverMessage, actionFeedback)`。正式 UI 在 `updateScreen` 用此方法選擇實際可見控件；測試傳入訊息鍵，直接斷言同一選擇的可見內容，無須初始化 Minecraft 畫面。

測試供應的 `serverMessage` 是伺服端同步文字的輸入替身；本步不聲稱已執行 Session 網路整合或遊戲視覺驗收。第⑦步可復用此接點接上其服務端情境測試。
