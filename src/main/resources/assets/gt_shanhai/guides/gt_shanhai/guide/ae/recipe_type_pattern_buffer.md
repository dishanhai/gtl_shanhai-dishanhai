# 星律样板总成

<Column gap="15" fullWidth={true}>

<Row>
    <BlockImage id="gt_shanhai:recipe_type_pattern_buffer" scale="6" />
    <BlockImage id="gt_shanhai:recipe_type_pattern_buffer_proxy" scale="6" />
</Row>

<Column gap="2" fullWidth={true}>

星律样板总成是一种**配方类型感知的 AE2 处理样板缓冲器**。它在 GTLCore 样板总成的基础上，为每个样板槽位记录并识别对应配方的**配方类型**，使宿主机器能按类型约束配方执行。

* 本体继承 GTLCore 样板总成完整能力，并复用分页样板槽界面（默认 9×6×3 = 162 槽）。
* 每个样板槽位绑定一个配方类型 ID，放入时自动读取样板内含配方类型。
* 当宿主机器配方搜索时，星律样板总成只提供**配方类型匹配**的样板给宿主执行。
* 样板槽位数量、每行数量、每页行数和最大页数可按配置调整。

</Column>

<Column gap="2" fullWidth={true}>

## 工作原理

### 配方类型记录

星律样板总成在放入样板时，自动从样板 NBT 中读取 `gt_shanhai_recipe_type` 字段，记录为该槽位的类型约束：

```
样板槽位 0: 切割(gtceu:cutter)
样板槽位 1: 组装(gtceu:assembler)
样板槽位 2: 化学反应(gtceu:chemical_reactor)
```

### 配方执行过滤

当宿主机器运行时，如果当前配方类型与样板记录不一致，该样板对这个配方**自动过滤**（不参与搜索）。这样：

- 通用加工厂等**多配方类型机器**可在同一宿主内装入不同类型样板
- 避免"跑着切割机配方时被铸造样板提示产出"的干扰
- 不依赖样板本体手动切换配方类型，靠**静默过滤**实现隐形转接

### 与通用样板总成的区别

| 对比项 | GTLCore 通用样板总成 | 星律样板总成 |
|------|------------------|----------|
| 多类型兼容 | 手动选择 | 自动过滤 + 混装 |
| 跨类型执行 | 不支持 | 默认不支持（可选开启，会绕过宿主配方类型限制） |
| 数据持久 | AE 样板 | NBT + 机器内存 |
| 虚拟供料 | 无 | 有（首配路径，按预算从 ME 网络真实提取原料） |

</Column>

## 使用场景

### 场景 1：通用加工厂多样板

**宿主机器：** 通用加工厂（支持切割、冲压、锻造）

**配置方式：** 装入星律样板总成，在同一台机器内配置不同类型样板：
- 槽 0-20: 切割配方样板
- 槽 21-40: 冲压配方样板  
- 槽 41-60: 锻造配方样板

**运行结果：**
- 机器搜索切割配方时 —— 自动过滤，仅执行槽 0-20 的样板
- 机器搜索冲压配方时 —— 自动过滤，仅执行槽 21-40 的样板
- 机器搜索锻造配方时 —— 自动过滤，仅执行槽 41-60 的样板

### 场景 2：避免配方窜线

**普通样板总成的问题：**
- 同一台机器既运行 A 类型配方又运行 B 类型配方
- AE 计划显示的"产出预览"混杂了两种类型的预期产出
- 玩家容易把样板放错位置，导致执行错误配方

**星律样板总成的改进：**
- 每个样板槽位自动约束配方类型
- 即使样板位置放错，机器也会自动过滤，不执行
- 完全消除配方窜线风险，提高多类型机器的易用性

</Column>

## 使用方式

### 基础装置

1. 把 <ItemLink id="gt_shanhai:recipe_type_pattern_buffer" /> 作为**样板输入仓室**放入多配方类型宿主机器的多方块结构。
2. 开启或重组机器后，星律样板总成自动在 GT 侧被识别为有效输入仓。
3. 通过宿主 AE2 接口向星律样板总成下单处理样板（操作方法与通用样板总成相同）。
4. 侧边栏「库存输入配置」子页最多可配置 32 个物品 + 流体输入格；也支持从**山海样板终端**远程打开"单槽催化剂配置"和"库存输入配置"子界面，无需靠近机器本体。

### 通配符样板（需加载 wildcard_pattern）

星律样板总成左侧配置栏提供独立的**通配符样板**入口，含 5 个母槽（数字按钮切换）。放入通配符样板后，GTLCore 会按样板中的材料筛选条件展开普通处理样板；展开结果占用独立的额外槽位（不挤占普通样板槽），继续经过星律的配方类型过滤和库存输入拉取。

每个母槽可指定展开的配方类型：

- **自动识别（默认）** — 在全部配方类型范围内搜索匹配的配方；如果同一组输入输出在多个类型下都能匹配，可能选中错误的类型。
- **指定类型** — 只能从当前宿主 `getRecipeTypes()` 实际拥有的类型里选择；展开样板中配方类型对不上的会被直接丢弃，不生成槽位（用来防止通配符展开爆量）。

更换任意母槽内容或重新指定类型时，旧展开槽的输入会先退回 ME 网络，再重新生成展开集合；相同的展开样板会自动去重。需要同时装有 wildcard_pattern 模组和 GTLCore 通配符兼容层才能使用，缺失时通配符槽区整体停用，不影响其余普通样板槽。

### 槽位代理

需要跨越较远距离或规避方块碰撞时：

1. 用数据棒右键**本体**复制绑定信息。
2. 用数据棒右键 <ItemLink id="gt_shanhai:recipe_type_pattern_buffer_proxy" /> **代理**执行粘贴，绑定到本体坐标。
3. 代理是本体在宿主结构里的一个"影子接口"：把本体的全部样板槽位、缓存和界面原样转发给宿主，代理本身不存料、不存样板。本体只需和代理同维度、所在区块已加载，可以放在宿主结构之外的任意位置——不存在"以代理为中心扩展取样"的距离/范围限制。
4. 代理未绑定本体时右键无法打开界面。

### 配置调整（可选）

星律样板总成默认使用 9×6×3 配置。如果需要修改：

```
配置文件 gt_shanhai-common.toml 的 recipe_type_pattern_buffer 段：
- patternsPerRow（默认 9）
- rowsPerPage（默认 6）
- maxPages（默认 3）
- virtualSupplyBatchParallel（默认 65536，单个样板槽位单次虚拟供料的目标并行批量上限）
```

在 Minecraft config 目录编辑配置文件后重启游戏。**已放置的总成也会在下次区块加载时采用新配置**；
调小 patternsPerRow / rowsPerPage / maxPages 会裁剪槽位，被裁槽位里的样板会掉落在机器位置（内部缓冲料无法保留），改小前请先清空高位槽的样板。

## 配方类型执行范围

### 类型收窄与执行队列

样板配方要进入宿主执行队列，必须先通过配方类型校验：

* **默认情况下**，样板携带的配方类型必须存在于宿主 `machine.getRecipeTypes()` 里，否则该样板整体不参与执行——连虚拟供料都不会触发，不会白占 ME 网络库存。
* 通过校验的样板配方会作为完整 GT 配方追加进宿主的候选执行队列，不要求宿主当前 `activeRecipeType` 与样板类型一致。
* **多类型混装** — 同一宿主内可同时装入不同配方类型的样板一起参与执行，前提是每种类型宿主都原生支持。

### 切换模式（可选）

行为由配置项 `DShanhaiConfig.recipeTypePatternSwitchMode` 控制：

* **VIRTUAL_ACTIVE_TYPE（默认）** — 不要求可编程仓，不切换宿主的 `activeRecipeType`，直接把通过类型校验的样板配方加入候选队列；仍然遵守"宿主必须支持该类型"的限制。
* **PROGRAMMABLE_HATCH_REQUIRED** — 严格模式。要求本轮收集到的样板配方类型唯一，且需要山海可编程仓随主机成型并成功把宿主 `activeRecipeType` 真实切换过去才执行；没有可编程仓、或本轮类型不唯一时该批次不执行。

两种模式都**不能**绕过宿主自身的配方类型限制，只是联动宿主的方式不同。

### 绕过宿主类型限制（默认关闭，请谨慎开启）

配置项 `recipeTypePatternAllowUnsupportedHostRecipeTypes`：

* `false`（默认）— 样板配方类型必须出现在宿主 `getRecipeTypes()` 里，否则不进入执行队列。
* `true` — 旧兼容行为，允许完整 GTRecipe 跨宿主配方类型虚拟直跑，宿主完全不需要原生支持该类型。**会绕过机器配方类型限制，开启前请自行评估影响**。

### 虚拟供料（首配路径）

样板槽**首次被 AE 下单**、或已激活槽的编程电路缓存损坏需要修补时，星律样板总成会主动从无线 ME 网络按 `virtualSupplyBatchParallel` 预算真实提取原料填入槽位——这是**一次性预算**，不是无限自动补货：预算随实际提取量递减，扣到 0 就不再补，直到样板被 AE 取出重新下单才重置为满预算。催化剂 / 不消耗输入 / 编程电路不会走真实提取，只建立虚拟在场标记。

这一机制与上面的"类型执行范围"相互独立：不被宿主支持的配方类型，连虚拟供料都不会发生。

### 当前版本边界

* **不生成 ticket/slot lock** — 样板执行沿用宿主原生 GT 配方逻辑，不额外加锁。
* **无并行倍增** — 并行上限由宿主机器决定，星律样板总成本身不调整执行并行数（对 AE 展示的产出倍率见下节，作用对象不同）。

## 星律样板产出倍率

星律样板总成额外提供**产出倍率**功能：按倍数重写它暴露给 AE 网络的样板产出（输入保持不变），让 AE2 的合成规划显示与宿主实际产量对齐。**它本身不会让机器多产，只改样板对 AE 声明的产出数字。**

* **仅对原初引擎宿主有意义** — 倍率来源固定读取当前连接控制器里的 `PrimordialOmegaEngineMachine`（原初引擎本体）或 `PrimordialOmegaEngineModuleBase`（其模块）挂载的产出倍率，其它宿主一律视为 1×。
* **开启方式** — 侧边栏「星律样板产出倍率」子页：
  - **开关** — 启用/关闭倍率改写
  - **读宿主** — 从当前连接的原初引擎读取倍率并锁定跟随（每 40 tick 自动轮询，宿主倍率变化会自动跟着重写样板）
  - **读样板** — 从槽位内样板已有的倍率标记反推填入
  - **刷新内部样板** — 手动强制按当前倍率重新改写全部槽位样板
* **倍率范围** 1~1000，同时作用于普通样板槽和通配符展开槽。
* **改写会清缓存并退料** — 每次改写生效的槽位会清空配方缓存，并把该槽已有的内部缓冲料退回 ME 网络，再按新倍率重新生成样板。

⚠ **请勿在非原初引擎宿主上手动开启并设置 >1 倍率**：宿主实际只产 1 份，样板却对 AE 声称 N 倍产出，会导致 AE 合成任务因产出不足而永久卡住。

## 常见问题

### Q: 能否在 GTCEu 原生机器（如通用加工厂）里用？
**A:** 是的。只要该机器支持 ME 样板缓冲器能力（`IMPORT_ITEMS` + `IMPORT_FLUIDS`），星律样板总成即可作为仓室接入。

### Q: 样板放错位置了怎么办？
**A:** 机器会自动过滤类型不匹配的样板。放错位置不会导致配方执行，但建议整理后再次操作。

### Q: 为什么装入的样板一直不执行，明明配方本身没问题？
**A:** 默认配置下，样板配方类型必须出现在宿主的配方类型列表（`machine.getRecipeTypes()`）里才会进入执行队列。确认宿主原生支持该类型；如果确实需要跨类型虚拟直跑，可在配置文件里开启 `recipeTypePatternAllowUnsupportedHostRecipeTypes`（会绕过类型限制，请自行评估风险）。

### Q: 能否混合多个样板总成（星律 + 通用）？
**A:** 可以。两种样板总成在同一宿主内会一起参与配方搜索。星律样板总成做类型过滤，通用样板总成不做过滤，两者互补。

### Q: 产出倍率能在普通机器（非原初引擎宿主）上开吗？
**A:** 不建议。非原初引擎宿主读到的倍率永远是 1×，手动设更高倍率只会让 AE 误以为能产更多，实际产出跟不上，合成任务会卡住。

### Q: 代理右键没反应，打不开界面？
**A:** 代理还没绑定本体。用数据棒右键本体复制绑定信息，再右键代理执行粘贴。

### Q: 为什么我的宿主机器没有识别到星律样板总成？
**A:** 确认：
1. 机器多方块已正确成型
2. 星律样板总成放在宿主允许的仓室位置（通常是结构外框 / 特定槽位）
3. 游戏日志中无 "ERROR" 关键字
如仍有问题，报告详细日志。

### Q: 样板类型是如何记录的？
**A:** AE2 模式编码 UI 中生成的样板会自动包含 `recipe_type` 信息（由 GT 贡献）。星律样板总成读取这个信息，无需手动填写。手写样板则需确保包含 `gt_shanhai_recipe_type` NBT 字段。
