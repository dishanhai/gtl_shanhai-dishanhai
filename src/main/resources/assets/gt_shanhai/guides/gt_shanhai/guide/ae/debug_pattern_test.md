# 山海配方样板调试工具

<Column gap="15" fullWidth={true}>

<ItemImage id="gt_shanhai:debug_pattern_test" scale="4" />

<Column gap="2" fullWidth={true}>

山海配方样板调试工具是面向配方/整合包调试的辅助道具，继承自 GTLCore 的样板调试工具并做了本地化增强：批量生成指定配方类型的 AE 处理样板、批量修改已有样板的产出倍率，以及扫描某个配方类型是否存在会被错误匹配的配方冲突。**不是"星律样板总成"的运行时监控器**，而是离线/调试场景下用来准备测试样板、排查配方冲突的工具。

* 所有配置保存在**物品自身的 NBT** 里，不同玩家手上的工具互不干扰。
* 支持完整配方类型 ID（如 `gtceu:cutter`）；省略命名空间时默认按 `gtceu:` 补全。

</Column>

<Column gap="2" fullWidth={true}>

## 交互方式

| 操作 | 效果 |
|---|---|
| 右击空气 | 打开设置界面（生成/分析 + 样板修改两个标签页） |
| 右击方块 | 无实际效果，只在动作栏提示"右击空气打开界面" |
| 潜行右击方块 | 把当前"样板修改"标签页的参数应用到目标 |

潜行右击的目标只认三类，其余一律拒绝并在动作栏提示"目标必须是样板供应器或样板总成"：
1. AE2 电缆总线上的**样板供应器**面板
2. 独立放置的**样板供应器 / ME 接口**方块
3. GTCEu 的**样板总成**机器（含 <ItemLink id="gt_shanhai:recipe_type_pattern_buffer" /> 星律样板总成）

</Column>

## 标签页一：生成与分析

### 配方冲突分析

填写配方类型 ID + 编程电路号，点击「开始分析」，扫描该类型 + 该电路号下是否存在**输入相同但会被匹配到错误配方**的冲突。**结果只写进服务端控制台 / latest.log，不会显示在聊天框**，看不到反馈时先去看日志。

### 样板生成

填写配方类型、编程电路号、样板倍率，以及输入/输出的白名单/黑名单关键字（空格分隔多个关键字），点击「获取样板」按量生成处理样板：

* 所有**不消耗的物品输入**（chance = 0 的辅助材料等）会被强制包装成"虚拟物品供应器"，编程电路例外，始终保留原始物品。
* 样板会写入两行说明：配方类型 + 电路号，以及电压档位 + EU/t。
* 生成数量 **≤ 20** 时直接塞进背包（放不下就掉地上）；**> 20** 时打包成一张超级磁盘阵列（命名"山海样板调试结果 (N)"）统一发放。

</Column>

## 标签页二：样板修改

对准备好的目标（样板供应器或样板总成）批量重算已有样板的产出，字段：

| 字段 | 作用 |
|---|---|
| 全局 × | 输入和输出同时按此倍数放大 |
| 全局 ÷ | 输入和输出同时按此除数缩小——**必须整除，除不尽整张样板直接判定失败** |
| 输出 × | 在全局倍率之后，只对输出再额外放大（不要求整除，超出上限会截断） |
| 输出 ÷ | 在全局倍率之后，只对输出再额外缩小（同上，截断而非失败） |
| 物品上限 / 流体上限 | 单项数量上限（默认各 100 万），超过会截断 |
| 应用次数（1~16） | 把以上整套规则重复应用几遍 |

潜行右击目标后，会对目标内每张样板逐一处理并回报"样板修改完成：成功 N，跳过 N，失败 N"：

* **跳过** = 该槽位解码不出有效样板
* **失败** = 全局除数除不尽 / 结果超限 / 重新编码后配方类型对不上原样板，原样板保持不变
* 修改会保留原样板 NBT 里除输入输出外的其余全部信息（配方类型标记、数量等）

## 常见问题

### Q: 点了「开始分析」聊天框没反应？
**A:** 冲突分析结果只写进服务端日志（latest.log），不发聊天消息，去看日志。

### Q: 样板修改一直"失败"？
**A:** 最常见的原因是「全局 ÷」没能把数量整除——全局除法要求必须整除，除不尽就整张样板判失败；也可能是重新编码后配方类型和原样板对不上。

### Q: 生成的样板去哪了？
**A:** 数量 ≤ 20 直接进背包（装不下会掉在地上）；> 20 会打包成超级磁盘阵列一次性发放，避免刷屏塞背包。
